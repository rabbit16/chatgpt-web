## 1. 一句话方案

**把 `/agent` 做成「取件窗口」：打开第一屏就是三个可一键复制的值，选完软件立刻看到"这 5 个框填什么"，而"软件里怎么点到那个框、报错怎么办"全部推给 `/guide`——同一段内容只出现一次。**

一句话给站长听：**「接入」是取件窗口（拿地址拿密钥），「接入教程」是说明书（教你怎么贴）。**

### 3.7 390 关键规格：长地址「不折成灾难」

**现状实测（必须修）**：390 下 `code` 框仅 **156px** 宽，`white-space:normal` + `word-break:break-all`，22 字符地址被切成 **3 行**，视觉上像 `https://www.rabbi / tj.top/v1`。

> **复核更新（22:12）**：并行实现已把 `break-all` 改为 `nowrap + overflow-x:auto`，**折行问题已消失**。
> 但出现**更危险的新问题**：`.copyValue` 是 `flex:0 0 auto; max-width:60%` 且手机只放宽到 `max-width:100%`，`copyRow` 仍是横向 flex（code + 40px 按钮同行），于是 code 被压到 156px，`scrollWidth` 219px → **地址尾部被裁掉**，屏幕上看成 `https://www.rabbitj`（`.top` 和 `/v1` 不见）。
> **用户会误以为地址就是这个**，比折行更容易抄错。这是 390 的首要问题。

| 规则 | 规格 |
|---|---|
| **R0 优先级** | **"能看全" > "不断行"**。地址必须一行内**完整可见**，允许滑动的兜底不能成为默认体验 |
| R1 换行策略 | `white-space: nowrap`；**禁止** `word-break: break-all`；`overflow-wrap` 不参与 |
| R2 溢出处理 | `overflow-x: auto`，`-webkit-overflow-scrolling: touch`，隐藏滚动条（`scrollbar-width:none` + `::-webkit-scrollbar{display:none}`） |
| **R3 值卡布局（关键）** | 手机下 `.copyRow` 必须 `flex-direction: column`；`.copyValue` 必须 `flex: 1 1 100%; max-width: 100%; width: 100%`（**取消 `flex:0 0 auto` 与 60% 限制**）；`code` `flex:1 1 auto; min-width:0`。目标：**code 独占整行 ≈ 300px**，当前域名 12px 等宽仅需 ≈170px，**完整可见、无需滑动** |
| R4 地址字号 | 手机 12px（`https://www.rabbitj.top/v1` 22 字符 × ≈7.2px ≈ 158px，300px 内富余） |
| R5 兜底 | 仅在**换域名后确实超宽**时才允许省略：`text-overflow:ellipsis`，且**必须**同时保证复制按钮复制完整值。省略时不得只显示半截而不给提示 |
| R6 反例 | 不允许 `font-size < 11px` 硬塞；不允许把地址拆成两段展示；**不允许"可滑动但没有任何视觉提示"地藏掉尾部** |
| R7 对照表同规则 | `.row` 手机改两行：第一行框名+说明，第二行 code+复制；code 同样独占行宽 |

**实测目标（验收口径）**：390 下每个地址 `code`：
1. `getBoundingClientRect().height / lineHeight === 1`（单行）；
2. **`scrollWidth <= clientWidth + 1`（完整可见，无需滑动）** ← 当前实测 219 > 154，**未达标**；
3. 页面 `document.documentElement.scrollWidth === innerWidth`（无整页横滚）。

## 4. 三个关键取舍

### 取舍 1 · 导航位置：推荐 **并存 + 改名**（方案 B）

| 方案 | 做法 | 1440 实测 | 390 实测 | 风险 |
|---|---|---|---|---|
| A 只改名 | `/guide` 改名「接入」，`/agent` 作别名 | 8 项 767px，余量 124px ✅ | 抽屉 7 行 | 教程仍背"接入"名，值还在里面，**问题没解决** |
| **B 并存+改名（推荐）** | 新增「接入」`/agent`；「接入指南」→「接入教程」`/guide` | 9 项 **839px**，余 124px（≥1280 都不挤）✅ | 抽屉 **8 行 ×59px**，不压标题 ✅ | 导航多一项；1100 以下需收紧 |
| C 并存+不改名 | 新增「接入」，保留「接入指南」 | 9 项 839px | 8 行 | 「接入」「接入指南」**字数太近看混**，且与用户原话"找了半天"矛盾 |
| D 替换 | 「接入」取代原项，删「接入指南」 | 8 项 767px ✅ | 7 行 | 丢掉 622 行教程（界面截图/排错），**不可接受** |

**实测依据（浏览器注入第 9 项测量）**
- 1440：8 项 767px → 9 项 839px，右侧操作区仍在原位，间距恒为 124px，**不换行不裁切**。
- 1280：9 项 839px，仍有 124px 余量 ✅。
- 1100 及以下：导航开始裁切（**既有问题**：现在 8 项在 1024 就已 `overflow:true`），与本方案无关，不计入本次负担。
- 390：整片导航收进「菜单」抽屉，每行 59px，竖向滚动；**多一项只多 59px 一行，不影响标题与首屏**。

**推荐 B 的理由**：① 用户要的是"单独一个小按钮"，B 直接满足；② 改名解决"接入 / 接入指南"混淆；③ 两项职责一眼可分：**接入=拿值**，**接入教程=照着做**；④ 手机端成本仅为抽屉里多一行。

**导航位置（两项之间）**：`充值商城 → 接入 → 接入教程 → 软件商城`。理由：充值完第一件事就是拿密钥；且「接入」必须排在「接入教程」**之前**——否则用户又被引去教程。

**320 下的兜底**：若站长担心 1100–1150 区间，可在 `<1200px` 把导航项 `padding` 从 12 收到 10（省约 40px），**不建议**为此加「更多」下拉。

### 取舍 2 · 与教程的分工：推荐 **拿值 vs 照着做**，复制 UI 只留一处

| 内容 | 归属 | 理由 |
|---|---|---|
| 两个接口地址 + 复制 | **`/agent`（唯一）** | 用户点名找不到的就是它 |
| API 密钥 + 复制/生成/管理 | **`/agent`（唯一）** | 一把密钥配所有软件，属"取件" |
| 模型名（gpt-/claude-） | **`/agent`** | 属"填什么值" |
| 每个软件的框名对照（5~6 行） | **`/agent`** | 属"填什么值" |
| Claude-haha 安装下载 | **`/guide` 第 1 步**（`/agent` 只在"其他"里给一句链接） | 属"怎么做" |
| 软件界面上哪个按钮、点哪里（真实截图） | **`/guide` 第 3 步（唯一）** | 属"怎么做" |
| 401 / 找不到模型 / 404 排错 | **`/guide` 第 4 步 + FAQ** | 属"出问题怎么办" |
| 自己写代码调接口（DocsPanel） | **`/guide` 折叠区** | 深度内容 |
| 图片模型怎么填 | **`/guide`**（`/agent` 不放） | 低频 |

**必须消除的重复（当前实现已违反）**：`/guide` 第 2 步整块「复制地址和密钥」与新页完全重复，两页各有一套复制 UI，改地址时会漏改一处。
**处理**：`/guide` 第 2 步**压缩为一段话 + 一个跳转**——

> 「地址和密钥在 **接入** 页，那里一键复制 →」
> 按钮：`去接入页拿地址和密钥`（`<Link to="/agent">`，主按钮）

教程仍可**引用**值（如第 3 步示意图里的占位），但**不再提供复制按钮**，也不再并排展示两个地址。这样"同一段内容不出现两遍"。

> **并行实现已按此方向改（2026-10-24 22:10 复核）**：`/guide` 第 2 步已改为「拿到地址和密钥」+ 主按钮「去「接入」页拿」，原两个地址收进可展开的「就想在这一页复制地址和密钥」里。
> **⚠️ 但这留下一个残余重复**：展开区里仍有第三套复制 UI。建议**去掉该展开区**（或只留一个"复制 OpenAI 地址"的极简行），否则换域名时三处都要改。
> 若担心"中途跳走会断"——解法是把 `/guide` 第 3、4 步需要的值改成**行内引用**（如「用上面拿到的地址」），而不是再放一份可复制副本。

**互跳（各一处，不循环堆砌）**
- `/agent` 底部：`不知道填在哪？看接入教程 →`（`/guide`）
- `/guide` 第 2 步：`去接入页拿地址和密钥 →`（`/agent`）
- `/guide` 顶部不加；`/agent` 顶部保留一个轻量「看完整教程 →」（现状已有，保留）

### 取舍 3 · Hero 放几个值：推荐 **3 个（2 地址 + 1 密钥）**

| 方案 | 内容 | 评价 |
|---|---|---|
| 1 个 | 只给 OpenAI 地址，密钥在下 | ❌ 密钥仍要滚，没解决核心问题 |
| 2 个 | 一个地址 + 密钥 | ⚠️ Claude-haha 用户（主推客户端）拿错地址，必报 404 |
| **3 个（推荐）** | OpenAI 地址 + Anthropic 地址 + 密钥 | ✅ 覆盖两种协议，复制即用；首屏仍装得下（实测） |
| 4 个+ | 再加模型名 | ❌ 模型名是"填什么"不是"拿什么"，且首屏会被挤到折叠线下 |

**为什么不是 4 个**：模型名有 2 个（gpt / claude）且会随价目页变化，放进 Hero 会稀释"两个值"的焦点。模型名**放进对照表**——用户反正要滑到那张表。
**为什么保留 2 个地址**：Claude-haha 是主推客户端且默认 Anthropic 格式，只给 `/v1` 那条会让主路径用户直接报错。两个地址各带一行「谁填这条」，用户不用判断。

### 6.1 安全项（本次评审发现，**建议一并修**）

> 截图取证时发现：`ApiKeyPanel`（`embedded`，即页面里的「管理密钥」区）会把**完整密钥明文**渲染成可见文本，整页截图 OCR 就能读出 `sk-…` 全串。
> 评审中我误存了两张含密钥的整页截图到 `shots/`，已被 `leak_guard` 拦下并删除；但**页面本身的设计问题仍然存在**。

| 项 | 要求 |
|---|---|
| 列表显示 | 密钥列表一律显示**打码值**（`sk-38b8…b38f`）；完整值只在点击「复制」时从内存取，**不作为可见文本渲染** |
| 原因 | 截图、录屏、远程协助、浏览器翻译插件都能读可见文本；打码后即使外泄也不可复用 |
| 改法 | `ApiKeyPanel` 里 `<code>{secret}</code>` → `<code>{item.key_mask || mask(secret)}</code>`；`CopyButton` 仍传完整 `secret`（复制取内存值，不要求可见） |
| 首屏密钥行 | 保持打码——**现有实现已符合**（`keyDisplay`），只需让列表口径与首屏一致 |
| 截图纪律 | `docs/audit/**` 整页截图若含密钥区，**必须打码后再入库**；提交前跑 `leak_guard` |
