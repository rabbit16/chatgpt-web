# 模型广场 · 搜索功能界面设计规格（v1）

> 目标页面：`/price` 下半部「完整价目」表（厂商页签 + 模型表格）
> 需求原话：「就是模型广场，能不能来个搜索功能，就是搜模型关键字，能蹦出来这个模型」
> 已定决策：**全局搜索，忽略厂商页签**
> 设计日期：2026-10-24 ｜ 性质：只读设计规格，不含代码改动

---

## 0. 现状核对（实测，重要）

工作区 `src/pages/price/index.tsx` 里**已有一版未提交的搜索实现**（状态、过滤、命中数、页签降权都在），但界面未收口。实测截图见同目录 `final-1440-*.png` / `final-390-*.png`。

已确认的 5 个问题（本规格逐条给出修正值）：

| # | 问题 | 实测证据 |
|---|---|---|
| 1 | 搜索时**所有页签一起变灰**（含「全部」），看不出「现在是全部厂商范围」 | `tabActive` 在 `searching` 时被强制去掉 → 8 个药丸全灰 |
| 2 | 手机端搜索框 **54px 高**，页签 36px，一大一小明显不齐 | 390 下 wrapper `height:54px`（内部 input 被 40px 热区规则撑高） |
| 3 | 想做药丸圆角，被 `global.less` 的 `border-radius:12px !important` 覆盖，实际仍是 12px | 计算样式 `border-radius:12px`，样式里写的 `--radius-pill` 未生效 |
| 4 | 无结果时，表格内仍显示 antd 默认「暂无数据」大空框，和上方「找到 0 个模型——换个关键词」重复 | 截图 `final-1440-noresult.png` |
| 5 | 不支持空格分词（`gpt sol` → 0 条）；无命中高亮 | 实测 `GPT 6`、` gpt sol` 均 0 条 |

实测基线尺寸：1440 下卡片内宽 **1110px**；页签槽 **529×36px**（8 个药丸，13px，全圆，选中 `--brand-soft` + `--brand` 600）；表格列宽合计 1180px。

---

## 1. 一句话方案

**搜索框长在「完整价目」标题行的右侧、独占 320px，厂商页签整条下移到第二行**；搜到内容时「全部」保持高亮、其余页签降到 55% 透明度，用「范围=全部」而不是「什么都没选」来表达全局搜索。

## 2. 设计规格表

### 2.1 布局骨架

```
1440                                    390
┌───────────────────────────────┐      ┌──────────────────┐
│ 完整价目 当前可用模型·最新在前   [🔍 搜索模型名或 ID ] │  │ 完整价目 …        │
│ [全部][OpenAI][Claude]…      找到 13 个模型          │  │ [🔍 搜索模型名或 ID] │
│ ───────────── 表格 ───────────── │      │ [全部][OpenAI]…  │
└───────────────────────────────┘      │ 找到 13 个模型     │
                                        │ ──── 表格 ────   │
                                        └──────────────────┘
```

- 桌面：标题行 = 标题（左）+ 搜索框（右）；页签行 = 页签（左）+ 命中数（右）。
- 手机：标题 → 搜索框（整行）→ 页签 → 命中数 → 表格，全部竖排。
- 相比现状，桌面多占 1 行（约 48px），换来「搜索（全局）」与「页签（筛选）」的物理分离。

## 3. 交互状态清单

| 状态 | 表现 |
|---|---|
| **默认** | 搜索框白底 1px 灰描边，图标 + placeholder「搜索模型名或模型 ID」；页签正常显示，「全部」高亮（若 tab=all）；无命中数行；副标题「当前可用模型 · 最新在前」 |
| **聚焦** | 描边变 `--brand`，外加 3px `--brand-soft` 光晕（全站统一，直接继承 `global.less`）；不改变布局、不弹下拉面板（本站不做搜索建议，避免和估算器下拉混淆） |
| **有输入（≥1 字）** | 抑制首尾空格后即生效；清除按钮出现；页签整体降透明度到 55%，**「全部」保持高亮**；副标题变「已在全部厂商中查找」；命中数行出现 |
| **有结果** | 命中数「找到 13 个模型」，数字品牌色等宽；表格只列命中项，**不限当前页签**（跨全部 8 个厂商）；匹配片段浅蓝底高亮（模型名与 ID 行都高亮）；分页保持 15/页 |
| **无结果** | 命中数行显示「找到 0 个模型」；表格区换成空状态：`IconBadge tone="sky"` 放大镜图标 + 主文案「没有找到「zzz」的模型」+ 副文案「换个更短的关键词试试；也可以清空搜索，看全部 58 个模型」+ 主按钮「查看全部 58 个模型」（点击=清空搜索）。**不再出现 antd「暂无数据」** |
| **清除** | 点 ✕ 或按 `Esc` → 关键词清空、焦点回到输入框；页签恢复常态（「全部」仍高亮）、命中数行消失、副标题复原、表格回到当前页签的完整列表（状态=默认） |

补充状态细节：

- **搜索时点页签**：清空搜索并切到该厂商（用户主动点页签 = 想按厂商看，搜索条件让位）。避免出现「点了没反应」。
- **搜索时页签数字**：页签本身**不加计数**。若将来要加计数，搜索态必须隐藏——计数语义是「本页签内数量」，与跨厂商搜索冲突。
- **输入不落 URL**：搜索是即用即走，不写 `?q=`，避免分享链接带回旧的搜索条件导致「页面一打开少了一半模型」。

## 4. 三个关键取舍

### 取舍一：搜索框与页签**同排**，还是**分两行**？

- **A 同排**（标题/搜索/页签挤一行）：省 48px 高度，但搜索框紧贴页签槽，读作同一控件组 → 用户以为「搜索只在当前页签里搜」，正好撞上已定的「全局搜索」。
- **B 分两行**（推荐）：搜索占标题行右侧，页签独立成条。
- **推荐 B**。理由（基于 1200/1280/1440/1600/1920 五档实测，非估算）：
  1. **语义分层**：全局检索 ≠ 列表筛选，同排会被读成一个控件组。
  2. **宽度余量实测**：现有同排 = 标题 203 + 搜索 220 + 页签 529 + 间隙 = 974px；1200 宽时卡片内宽仅 1019px，余量 **45px**。若按本规格把搜索框做成 **320px**，同排需约 1074px → **1200–1279 区间必然换行**，出现「工具区整体掉到标题下一行」的破版。分两行在任何宽度都稳定。
  3. 页签独占整行后 8 个药丸一次排开不换行（1440 下 529/1110）。
  4. 手机端本来竖排，两端可共用一套规则。

### 取舍二：搜索框圆角用**药丸**还是 **12px 方角**？

- **A 药丸 999px**：和旁边页签同族，像一体的筛选组件；但会被 `global.less` 的 `border-radius:12px !important` 覆盖，必须加 `!important` 打补丁，且暗示它也是「筛选」。
- **B 12px**（推荐）：符合 token 规则「控件 12 / 卡片 16 / 药丸 999」，站内所有输入框都是 12px。
- **推荐 B**。理由：搜索框是**输入控件**不是筛选药丸，圆角本身就是「可打字」的信号；且零冲突、零补丁，最符合「小改动、观感统一」。（现状问题 #3 就是因为选了 A 但没打过 `!important`，css 写了药丸、实际还是 12px。）

### 取舍三：搜索时页签**降透明保留**还是**整条隐藏**？

- **A 降透明 + 「全部」高亮**（推荐）：页签还在，用户能随时点某个厂商退出搜索。
- **B 整条隐藏**：更彻底地表达「页签不生效」，但页签区消失会让布局跳动，且用户失去「切回按厂商浏览」的出口。
- **推荐 A**。理由：搜索是「临时视图」，出口必须留在原地；只要保证**「全部」是亮的、其余是灰的**，用户就能读出「范围=全部厂商」，不会误以为功能失效（现状问题 #1 正是「全灰、没有一个亮」，看起来像坏了）。

## 5. 给前端的实现要点

**改哪里**

1. `src/pages/price/index.tsx`
   - 状态已存在，无需新增：`const [search, setSearch] = useState('')`（第 106 行）；派生值 `keyword / searching / searched / list`（第 271–288 行）已实现「搜索优先、跨厂商」。
   - 需要补 4 处：
     - a. **有效页签**：把渲染用的 `tab` 换成 `const effectiveTab = searching ? 'all' : tab`，只在页签高亮判断里用（无副作用，不要写 `useEffect` 去 `setTab`，否则会产生额外渲染与状态回写）。这样「全部」在搜索时保持高亮。
     - b. **点页签清空搜索**：页签 `onClick` 里先 `setSearch('')` 再 `setTab(key)`。
     - c. **分词**：`const terms = keyword.split(/\s+/).filter(Boolean)`，命中条件改为 `terms.every(t => id.includes(t) || name.includes(t))`（AND 语义）。单关键词时行为与现在完全一致。
     - d. **高亮**：写一个纯函数 `highlight(text, terms)` 返回 `ReactNode[]`，把命中片段包进 `<mark className={styles.hl}>`；模型名与 ID 行都调用。注意 `key` 用下标+片段序号。
   - 空状态：给 `<Table>` 传 `locale={{ emptyText: <搜索空状态 /> }}`，或在 `list.length === 0 && searching` 时条件渲染自定义空块、不渲染 Table（推荐后者，能顺手去掉外层横向滚动条）。
   - 搜索框补 `enterKeyHint="search"`（手机键盘显示「搜索」键）与 `aria-label="搜索模型"`（已有）。

2. `src/pages/price/index.module.less`
   - 新增/修正 4 个类：`.tableHead`（改两行结构）、`.modelSearch`（见规格表，**删掉 `--radius-pill` 那段无效覆盖**，直接用 12px）、`.searchMeta`（命中数，数字用 `--brand` + `tabular-nums`）、`.searchEmpty`（空状态）、`.hl`（高亮：`background: var(--brand-soft); color: inherit; font-weight: inherit; padding: 0 1px;`）。
   - 手机端在 `@media (max-width:768px)` 里：搜索框 `width:100%`，页签行与命中数行都左对齐。
     - **修 54px 偏高（现状问题 #2）**：390 下 wrapper 实测 `height:54px`，因为内部 `input` 被撑到 40px、再加 wrapper 上下 6px padding 与描边。做法是让 wrapper 定高、别让内部 input 撑开：
       `min-height: 40px; height: 40px;` 配合 `.ant-input { height: 100%; padding-block: 0; }`，并把 `font-size` 设 **16px**（iOS 聚焦不放大）。桌面仍保持 36px，与页签槽同高。
     - **修 12px 覆盖（现状问题 #3）**：删掉 `.modelSearch` 里 `border-radius: var(--radius-pill)` 那段（被 `global.less` 的 `!important` 覆盖，写了也不生效）。按本规格直接用 12px，不要加 `!important` 去打补丁。
   - 搜索态页签降透明：`.tabs button[data-muted]{opacity:.55}`（已存在，保留），但**高亮判断要用 `effectiveTab`**，别再把「全部」也置灰。

**防抖**

- **不要加防抖**。数据完全在内存里（公开价签 58 条），`Array.filter` 一轮 <1ms，加防抖只会让输入有延迟、光标处文字慢半拍。
- 若将来模型数涨到几百条以上再考虑，届时 **150ms** 足够（低于 150 用户感知不到延迟，高于 200 会觉得卡）。

**不要做的事**

- 不加搜索建议/联想下拉（会与估算器里的 `Select showSearch` 混淆，且要额外键盘交互）。
- 不把关键词写进 URL。
- 不改表格列宽、分页、横向滚动逻辑（搜索只是换 `dataSource`）。
- 不给页签加数字计数。

## 6. 已知限制（按站长已定范围，不在本次改）

- 只搜「模型名 + 模型 ID」，**不搜简介、不搜厂商名**：所以输入「智谱」得 0 条（「智谱」只是徽章文案，不在名字里），输入 `glm` 才有 4 条。缓解方式：placeholder 明确写「搜索模型名或模型 ID」，空状态副文案也提示「换个更短的关键词」。
- 大小写不敏感、首尾空格自动忽略（现状已满足，保留）。
- 中文可搜，但仅限字段里本就含中文的部分（当前模型名/ID 都是英文，实际以英文关键词为主）。
