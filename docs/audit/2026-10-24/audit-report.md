# 前端 UI 审查报告 · 2026-10-24

**范围**：`chatgpt-web`（分支 `feature/dev`）价格页 / 发票三处 / 用量页
**方式**：只读审查，未改动任何业务代码
**证据**：本地 `127.0.0.1:5173`（feature/dev 代码）+ 线上 `https://www.rabbitj.top`（旧版部署）对照，1440 / 390 双宽度截图见本目录

> 说明：线上环境是**旧版**，打包产物里还没有页头充值条；因此充值条相关结论以本地 dev 版本为准，其余（趋势图、移动端表格）线上与本地一致。

## 一、必须改（3 条）

### M1. 手机端价目表：固定「模型」列比屏还宽，价格永远看不到

**证据**：`audit-21-price-table-390-scrolled-end.png`（390 宽、表格已横向滚到最右）

**问题**：`src/pages/price/index.tsx:289-291` 把「模型」列设为 `width: 280` 且 `fixed: 'left'`。
在 390 视口下，表格可视区只有 **220px**，而固定在左侧的模型列实测 **292px**——固定列比可视区还宽，横向滚动时它一直压在最上层。

**影响**：手机上这个页面的核心信息就是价格，但用户划到最右也只看得到模型名和简介，**一个价格数字都读不到**。等于手机端价格页失效。

**最小改动**：
- `columns` 里模型列的 `fixed: 'left'` 改为**仅在 `≥720px` 时启用**（用 `window.matchMedia` 或 antd `responsive` 直接去掉固定），并把移动端宽度降到 `200` 左右；
- 或更省事：移动端把 `scroll.x` 调小（如 `720`），让前两列（模型 + 输入价）能同屏。
- 不要重排表格结构，只动列配置。

---

### M2. 充值条取余额的字段名写错了，登录后永远不显示余额

**证据**：接口实测（`/apiAI/user/get_user_info` 真实返回）+ `src/pages/price/index.tsx:168-181`

**问题**：接口原始响应是

```json
{ "code": "0", "data": "", "userMessage": { "user_id": 132, "token": 6.37, "plus_user_count": 0.7, ... } }
```

两个关键点：`data` 是**空字符串**；余额字段叫 **`token`**（数字），不是 `balance` 也不是 `money`。
经过 `src/request/index.ts` 的拦截器后，`res.code` 会归一成数字 `0`（所以 `res.code !== 0` 这一关能过），`res.data` 则回落成**整个原始对象**。
真正卡住的是**字段名**：`res?.data?.userMessage?.balance ?? ...?.money` 两个字段都不存在 → `balance` 永远是 `null` → 横幅退回访客文案。

旁证：钱包页 `src/pages/shop/index.tsx:333` 读的是 `res.data.userMessage.token`，同一份数据能正常显示「当前余额 6.890665」（见 `audit-08-wallet-1440.png`）。

**影响**：这条横幅的主要卖点「登录后显示当前余额」**从未生效**。已登录用户看到的仍是访客文案「充值后即可调用全部 58 个模型」，按钮写着「立即充值」——用户会以为系统没认出自己已登录。

**最小改动**：
- 取值改为 `res?.data?.userMessage?.token ?? res?.userMessage?.token`（**沿用钱包页的字段名**），并保留 `balance`/`money` 作为兜底；
- 顺手把写死的「58 个模型」换成实际模型数（如 `models.length`），否则模型增减后文案会过期；
- 建议给「已登录但余额取不到」单独一句文案（如「余额加载中 / 点击查看钱包」），不要和访客文案共用同一句。

**注意**：`user_info` 里的 `userId` 正常（132），登录态没问题，纯粹是取值字段不匹配。

## 二、建议改（3 条）

### S1. 充值条与下方页签/标题抢层级，且「我的发票」入口重复

**证据**：`audit-02-local-price-1440-anon.png`、`audit-06-invoice-1440.png`、`audit-03-local-price-390-anon.png`

**问题**：
- 1440 下充值条高 77px、占满整行，主按钮「立即充值」是页面最亮的元素；紧随其后的 H1「模型价格」被压到 y=249，视觉第一落点是「充值」而不是「我在看什么价格」。
- 390 下充值条从 77px 涨到 **169px**（占首屏 1/5），文案折成两行、两个按钮各占一半，H1 被推到 y=341，首屏基本只剩页签 + 充值条。
- 条内右侧的「我的发票 →」与上方页签「我的发票」是**同一个去处**（`switchTab('invoice')`），在发票页签下这个链接指向自己。
- 视觉上它夹在「页签」和「页面标题」之间，既不属于导航也不属于内容，层级含糊。

**影响**：价格页的主任务是「查价」，现在被充值诉求盖过；重复入口让人怀疑「发票到底有几个地方」。

**最小改动**：
- 只在 `viewTab === 'price'` 时渲染充值条（钱包/发票页签各自已有余额与开票入口，不必再重复）；
- 去掉条内「我的发票 →」这个次级按钮，开票入口保留页签即可；
- 390 下主按钮改为占满整行、删掉副按钮后条高可回到 ~110px 以内；
- 删掉 `index.module.less:29` 的 `margin-bottom: 18px`（外层 `.wrap` 已有 `gap: 20px`，现在是 38px 的叠加间距）。

---

### S2. 发票页三张汇总卡被拉伸成「空心大块」，充值记录每行一个同权重按钮

**证据**：`audit-10-invoice-1440-fullpage.png`、`audit-11-invoice-390-full.png`

**问题**：
- `.topGrid` 用 `align-items: stretch`（`src/pages/invoice/index.module.less:58`），左列三张汇总卡被拉到与右侧「怎么开发票」等高，单卡约 **118px**，文字却只有两行——大片留白，像占位没填内容。
- 右侧「充值记录」5 行里每行都挂一个蓝色描边「开发票」按钮，5 个同权重主操作并排，视觉噪音大，也分不清哪笔已经开过（已开票的只显示标签，边界还不明显）。
- 390 下「开票记录」标题被 `headActions`（下拉框 + 刷新）挤成**两行**；每个「开发票」按钮掉到记录下方单独一行，成了小色块。

**影响**：这是用户点进「我的发票」第一眼看到的画面，空心卡片会让人觉得「数据没加载出来」；按钮泛滥反而降低「去哪开票」的确定性。

**最小改动**：
- 汇总卡：`align-items: stretch` → `align-items: start`，或给左侧 `.summary` 设 `justify-content: flex-start` + 卡片固定 `min-height: 76px`，让三张卡自然高度；
- 充值记录里「开发票」由 `type="primary" ghost` 降级为 `type="link"`（与钱包页一致），已开票/审核中的记录整行降低不透明度；
- 390 下 `.headActions` 独占一行（已有 `width:100%` 规则，但 `.cardHead` 是 `flex-start` 未换行，补 `flex-wrap: wrap` 并把 `margin-left:auto` 在窄屏归零）。

---

### S3. 后台审核弹窗：通过/驳回共用一组输入，「驳回」按钮紧贴主操作

**证据**：代码审查 `src/pages/admin/invoices/index.tsx:247-290`（线上无待审数据，未能实拍弹窗）

**问题**：
- 「发票号」和「驳回原因」两个输入框**同时**展示，没有任何分组或视觉区分；用户不知道该填哪个。
- 底部按钮顺序是 `取消 / 驳回(danger) / 通过并填发票号(primary)`，danger 按钮紧挨主按钮，且两者都在 `loading={saving}` 状态下可点。
- 驳回原因只有 `placeholder` 提示「必填」，没有必填标记，也没有常用理由（「抬头/税号有误」「订单不支持开票」）可一键填入——站长每次都得手打。

**影响**：这是**唯一**会把错误发票发给用户的环节。误点「驳回」会让用户白等 1–3 个工作日；每次手打理由也拖慢审核。

**最小改动**：
- 弹窗内用 `Radio.Group`（通过 / 驳回）先选动作，再只显示对应输入框；或至少用两个 `Form.Item` + label 明确标注「通过时填」「驳回时填」；
- 驳回原因下方加 3 个常用理由的 `Tag`，点击填入（纯前端，不加依赖）；
- 「驳回」按钮移到弹窗左下角，与主操作分开至少 12px。

## 三、不用改（2 条）

### N1. 390 下三个页签不换行、页面无横向溢出

实测：三个页签宽 83px 均分 262px 容器，`tabsWrap=false`；价格页 / 发票页 / 用量页 `document.scrollWidth === 390`，**没有横向溢出**。
价目表、用量表的横向滚动都被限制在卡片内（`overflow: hidden`），窄屏观感可控。
`PillTabs` 的 `white-space: nowrap` + `≤430px` 收紧内边距已生效——这处之前修过，保持即可。

### N2. 充值条文字对比度、圆角与描边体系都合规

实测对比度：正文 `#475467` on `#e8f1ff` = **6.76:1**，标题 `#101828` on `#e8f1ff` = **15.6:1**，均过 WCAG AA。
圆角 16（卡片）/ 12（控件）/ 全圆（药丸）三档统一，1px 描边分层，没有多余阴影——符合现有约定。
唯一擦边项：主按钮白字 on `#1877ff` = **4.10:1**，13px 字号只差一点点到 4.5；如果顺手要动，把按钮底色换成 `--brand-hover #0b63e5`（约 5.2:1）即可，**不改也不算错**（大按钮/粗体场景 AA 允许 3:1）。

## 四、按原问题的逐项结论

| 审查项 | 结论 |
|---|---|
| 1) 价格页常驻充值条（1440 / 390 层级、对比度、与页签冲突） | 对比度合格（N2）；**层级与重复入口要改**（S1）；**余额字段名写错、登录后显示不出余额（M2）** |
| 2) 发票三处信息架构与状态标签 | 用户端已是「充值商城 › 我的发票」独立页签，留言墙只剩一条「发票」公告造成的误解，无需新增栏目；**卡片与按钮层级要收敛**（S2）；**后台审核弹窗要分组**（S3）；状态标签 `待审核/开票中/已开票/已驳回` 四色（gold/blue/green/red）一眼可懂，不用改 |
| 3) 近 14 天 Token 卡片稀疏数据 | **必须改**（M3）：空态/单点态表达 + 时区修正 + 390 峰值文案 |
| 4) 移动端 390 溢出/挤压 | 价格页三页签与开票列表**不溢出**（N1）；**价目表固定列遮挡是硬伤**（M1）；用量页峰值文案折行（并入 M3） |
