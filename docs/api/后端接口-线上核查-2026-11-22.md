## 需要站长确认的一条口径

**管理端鉴权依赖手机号，不能用 sk-。**

`_require_admin`（`main.py:3827`）要求 `user.is_staff`；
`lookup_user_by_credential`（`utils/api_key_auth.py:56`）只在凭据**非 `sk-` 开头**时
按手机号查 `tb_user`。

前端 `llmFetch`（`src/request/api.ts:648`）取凭据的顺序是
`llm_api_key`（sk-）→ 手机号。**管理员一旦在「接入」页创建并选中过 sk- 密钥，
后台所有 `/admin/*` 请求都会以 sk- 发出，解析到的用户若无 staff 标记即 403。**

联调时请确认：发起后台请求的管理员账号在 `tb_user` 里 `is_staff = 1`，
且用于该后台会话的凭据是手机号（或该 sk- 对应的同一管理员账号）。

## 前端侧的两个小风险（非阻塞）

1. **单 key 模型配置 `duration_minutes` 默认 5 分钟**，换算 `duration_seconds = 300`；
   后端 `SoftRouteUpsert` 允许 `10..86400`，300 合规。前端输入框无最小值校验，
   若用户填 0 会被前端 `Math.max(1, …)` 兜成 60 秒，仍合规。
2. **`fail_threshold` 前端表单无上下限校验**，后端限制 `1..20`；
   超出会收到 `422`，页面按 `llmFetch` 的错误提示展示。
   建议后续给表单补 `min=1 max=20`（属前端改动，本次未做）。
