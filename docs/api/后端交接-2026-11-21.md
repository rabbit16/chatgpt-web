# rabbitJ 前端改版 · 后端交接

- 交付分支 `codex/frontend-handoff-20261121`，基于 GitHub 发布分支 `release` 的 `67530d1`，集成前端设计版本 `85ab418`。部署机当前运行的提交需要站长核对。
- 本次改版沿用现有业务接口和模型网关。下面按前端实际调用整理契约。线上支付、开票和后台写入请在部署环境联调。

## 发布配置

| 项目 | 交付版约定 |
|---|---|
| 构建 | `npm ci` 后执行 `npm run build`，发布目录为 `dist/`。部署前沿用发布环境原有配置，变量清单见 [`.env.example`](../../.env.example)。 |
| 业务接口 | `VITE_APP_REQUEST_HOST` 指向业务接口根地址（例如同域 `/apiAI`）。登录、支付、开票等沿用 `token` 请求头。登录 `POST /user/verify` 读取响应的 `x-set-cookie`；跨域时需允许前端读取该响应头。业务成功码兼容 `0` 和 `"0"`，具体字段位置见下表。 |
| 模型网关 | `VITE_LLM_BASE_URL` 指向生产网关，通常为同域 `/v1`。模型和用量接口使用 `Authorization: Bearer <API_KEY>`。维持发布环境的路径转发规则，流式接口应允许回答分段到达浏览器。 |
| 直接打开页面 | `/chat`、`/price?tab=wallet`、`/result` 等前端路径应由网页服务器返回 `index.html`。业务及网关路径由相应服务处理。 |
| 本地演示 | `npm run start -- --mode rabbitj-demo --host 127.0.0.1` 用本地样例代替请求，只在本机开发模式启用。部署使用标准生产构建。 |

`VITE_` 配置会进入静态产物。支付渠道密钥和其他服务端凭据保存在后台。

## 页面依赖与联调

表中 `/user/…` 路径相对业务根地址，`/v1/…` 假定模型网关部署在同域 `/v1`。

| 页面 | 现有请求及前端依赖 | 站长联调重点 |
|---|---|---|
| 首页、模型价格、绘图价目 | `GET /v1/pricing/models`。`models`、`model_ids`、`image_models` 提供当前账号可用模型及价目。文本按美元/百万 tokens，输入、输出、缓存和各档位分别计费，图片按响应的 `billing` 和单位展示。 | 用普通账号核对三处显示的可用模型和账号价。官方对照价缺失时显示「官方价待核实」，官方价同步按约定暂缓。 |
| AI 工作台 | `GET /v1/models` 供选模型。对话按协议发 `POST /v1/chat/completions` 或 `POST /v1/messages`，以 `text/event-stream` 分段返回。`POST /user/createChat` 创建会话，`POST /user/getContextList` 读取历史，`POST /user/searchChat` 按关键字分页搜索。成功后通过 `POST /user/saveChatMessage` 保存，发送 `userId`、`contextId`、`prompt`、`gpt`、`mode`、`start_time`、`answer_time`。 | 确认回答边生成边显示，普通问答刷新后仍在原会话，点击停止后停止读取。重试持久化的限制见下节。 |
| AI 绘图 | `POST /v1/images/generations` 和 `POST /v1/images/edits`，结果读取 `data` 中的 `url` 或 `b64_json`。 | 核对文生图和参考图编辑的模型、尺寸及响应格式。 |
| Agent 接入 | `POST /user/api_key/list`；`POST /user/api_key/create` 传 `name`；`POST /user/api_key/enable`、`disable`、`delete` 传 `id`。列表读取 `keys`，条目含 `id`、`name`、`key_mask`、`is_active`、`created_at`，创建结果需有新建密钥的 `api_key`。 | 核对创建后的复制、选择当前密钥以及启用、禁用、删除。列表显示掩码。 |
| 用量记录 | `GET /v1/usage?limit=10&offset=0` 返回 `items`、`total`；翻页发 `offset=(页码-1)×limit`。每页 10、20、50 或自定义 1–200。`GET /v1/usage/summary` 沿用相同筛选条件，汇总请求省略分页参数。 | 核对筛选、翻页和总数。明细所需状态、金额和用量字段见[用量接口说明](../../src/docs/usage-api.md)。 |
| 钱包与支付结果 | `POST /user/get_user_info`、`POST /user/user_bill_list` 读取余额与账单。`GET /user/pay/channel` 取当前通道；虎皮椒 `POST /user/xunhupay/pay` 返回 `outTradeNo`、`payType`、`payUrl`，`GET /user/xunhupay/query/{outTradeNo}` 的 `paid: true` 表示入账；蓝兔 `POST /user/pay_rabbit` 读取 `data.payUrl` 里的 `code_num` 和 `data.QRcode_url`，用 `POST /user/verify_pay_again` 传 `codeNum` 查询。 | 用测试订单分别验电脑扫码、手机支付返回、取消或支付待确认、刷新原订单、支付成功后核对余额。查单和入账以服务端订单归属与结果为准。 |
| 开票 | `POST /user/invoice/summary`、`list`、`create`、`cancel`，后台沿用 `POST /user/admin/invoice/list` 和 `review`。 | 验证单笔与多笔开票，以及账单的 `invoice_status`、`invoice_id`。参数和旧接口兼容见[开票接口说明](invoice.md)。 |
| 软件商城 | `POST /user/software/list`、`POST /user/software/category/list`。列表的 `source` 区分 `official` 和 `user`，`links` 提供下载渠道。列表分页上限 50。 | 确认真实记录分类和仅有网盘链接的软件下载可用。参考[商城交接补遗](后端交接-增量-2026-10-25.md)。 |
| 公告留言 | `POST /user/announcement/latest`、`list`，`POST /user/feedback/list`、`POST /user/feedback`；管理端沿用 `/user/admin/feedback`、`update`、`delete` 系列接口。 | 用测试留言核对发布、回复和管理员操作。旧事项见[历史交接](后端交接-2026-10-25.md)。 |

## 待确认与已知限制

1. **聊天重试后的历史覆盖。** 重试能在当前页面更新回答，历史保存仍走新增接口 `/user/saveChatMessage`。此前演示中刷新会出现重复问答。请确认是否已有按单条回答 ID 覆盖的接口，或能否为保存接口增加替换语义。验收以刷新后原位置仅保留一条问答为准。整会话删除接口不适用于这一场景。
2. **商城官方价。** 本轮沿用现有设计的官方对照价展示，官方价自动同步暂缓。`original_*` 为空时显示「待核实」。现有后台「模型价」的原价配置说明涉及计费，发版验收时无需为填补展示而修改该配置。如后续要同步厂商价，单独约定展示字段，并为每项保留型号、档位、单位、来源和核实时间。
3. **历史接口事项。** 多笔开票、后台删除留言和商城 `source` 的旧交接记载了当时的接口状态。请以当前部署环境的联调结果更新状态。
